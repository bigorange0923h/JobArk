# JobArk 前端开发规则

本文件适用于 `frontend/` 内的改动；仓库根目录的 `AGENTS.md` 同时生效。这里约束界面一致性，不改变单人 V1 的业务范围。

## 视觉与布局

- 工作台采用统一的左侧导航、顶部工作区和内容区。导航项从 `src/app/router.ts` 读取；不要在页面里另建一套主导航。
- 导航参考 Arco Design Pro Vue 的简洁中台层级：图标与文字对应具体功能，选中态以统一主色和浅色背景表达；不添加数字序号、虚构菜单或纯装饰性控件。参考视觉不等于引入另一套组件库。
- 颜色、间距、圆角和表格基准样式以 `src/styles/theme.css` 的 `--ja-*` 令牌为准；Ant Design Vue 的主题色由 `src/App.vue` 的 `ConfigProvider` 同步设置。调整主色时两处一起改。
- 页面统一使用 `.page-header`，标题、辅助说明分别使用 `h1` 和 `.page-subtitle`；可选眉题使用 `.page-eyebrow`。主要操作放在页头右侧，内容分组用 `a-card`，组间距用 `.section-gap`。
- 卡片、表格和表单保持紧凑但可读：同类页面使用相同字号、留白、圆角和强调色；不要在各 `.vue` 文件里重复定义一套色板或写大段单行模板。
- 以桌面工作台为主要目标，同时保证窄窗口不出现横向页面溢出；宽表格允许自身横向滚动。不要为了追求“中台感”加入无业务用途的图表、虚构统计或装饰性功能。

## 组件与状态

- 交互控件优先使用项目已有的 Ant Design Vue：按钮、输入、选择、复选、表单、表格、卡片、提示和空状态。语义化 HTML 用于结构与内容，例如 `main`、`nav`、`section`、`h1`、`p`；避免同一页面混用浏览器默认样式和组件库控件。
- 每个读取页面明确区分加载中、空数据、请求失败和正常数据。失败展示后端安全文案；有 `request_id` 时保留可追踪编号，不用空态掩盖错误。
- 写操作要展示忙碌状态并阻止重复提交；显式确认、冲突处理、历史版本不可变等业务边界不能被视觉改动弱化。
- 表格列名、状态标签和时间格式使用清晰中文；可操作项要有明确动词。字段说明解释业务含义，不用“美观”文案替代真实反馈。
- 简历 A4 预览及打印遵守 `src/styles/print.css`，工作台外壳与主题样式不得进入打印页；调整外壳后要复查打印隐藏规则。

## 实施与验收

- 新页面先沿用现有外壳、组件、令牌和状态模式；只有现有模式不能覆盖需求时才新增通用组件或依赖。引用外部模板只借鉴可复核的布局和交互，不整套引入权限、多租户或无关框架。
- 改动交互时保持键盘可操作与可辨识的焦点状态，表单保留标签、必填提示和错误反馈。不要只凭构建通过宣称视觉验收。
- 提交前运行受影响测试、`npm run lint`、`npm run build`；改动页面布局或打印样式时实际检查桌面与窄窗口，并复查简历打印预览。未做的检查如实标记。

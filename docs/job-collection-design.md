# 招聘平台信息采集与导入设计

## 结论与事实

首版采用“平台适配 + 候选确认 + 版本化入库”。四站适配器解析用户已获得的内容，正式职位保留来源与不可变 JD 快照；自动网络访问尚不在本版范围内。

2026-10-02 官方条款核对：
- [领英](https://www.linkedin.com/help/linkedin/answer/a1341387/prohibited-software-and-extensions)：限制抓取插件及自动化。
- [Indeed](https://www.indeed.com/legal?hl=en_US)：自动访问需要明确许可，robots 仅提供特定条件许可。
- [BOSS](https://www.zhipin.com/web/common/protocol/protocol-2019-09-30.html)：限制爬虫、拟人程序等非正常读取方式。
- [51job](https://login.51job.com/xyservice.php?display=h5&page=1)：限制自动化接入、收集和处理平台内容。
这些证据不等于验证了各站当前 DOM、账户访问能力或获得 API 许可。首版不自动访问四站；未来每站分别证明许可与真实访问能力。

## 流程

用户打开职位 → 提供详情链接与已获得的正文/HTML → 本地适配器识别来源并提取候选 → 数据库存候选 → 用户核对与补全 → 事务确认 → 正式机会/页面/不可变快照。

首版适配器位于 automation/adapters，职责是白名单 URL 规范化和本地页面提取，不依赖数据库、LLM 或浏览器。JSON-LD 仅接受单个 JobPosting；缺失字段为空，不能读取网页 title 当职位名。HTML 不执行、不回显，解析后只保留正文与必要字段。原始输入只存 SHA-256，候选中留提取版本。

业务服务位于 modules/job：处理预览、24 小时过期、乐观锁、明确确认、人工修订审计、去重与入库。网络和登录状态不能成为事实来源；只有确认成功后的数据库内容进入匹配与投递准备。

## 数据与并发

多渠道浏览与匹配的静态核对、页面契约和待确认扩展见 [job-browsing-design.md](job-browsing-design.md)。当前适配器未提取独立平台发布日期，JobPosting 也无对应字段；日期声明应归来源页面，不归按正文去重的快照。建议扩展候选预览／确认来保留日期原文、精度与依据，未经确认不得当作现有接口。last_seen_at 表示正式接受内容的系统时间，不证明当时访问过平台；重复确认固定回执不算新的观察。

JobSource 增加 LINKEDIN / INDEED / BOSS / FIFTYONEJOB。页面唯一性沿用 (source, external_id) 和规范化 URL。跨平台同公司同标题可能不是同一机会，保持独立；日后人工关联需要独立需求，不先做相似度合并。

新增 job_import_candidates：平台、外部 ID、规范链接、输入哈希、提取器版本、原候选 JSON、人工确认 JSON、过期时间、目标页面及观察版本、确认页面/快照、状态和乐观锁。候选 JSON 只保存必要来源摘录，不保存整个 HTML。正式来源字段不能由确认请求改写。

按平台 + 外部 ID 取得 PostgreSQL 事务级 advisory lock；首次创建和重复导入串行。预览时若已有页面记录其版本，确认时校验，变化返回 409。没有页面的预览若确认时出现页面也返回 409。已有页面只更新 JD 及观察时间，不自动覆盖公司、标题、分类、备注。相同内容复用快照，旧申请与匹配引用不变。

同候选同确认载荷重复请求返回固定的机会、页面和快照 ID，不回读后来变化的 JD，不同载荷或版本拒绝；候选更新与正式写入同一事务。锁等待上限 5 秒、单条确认语句上限 15 秒，超时回滚并返回可重试的 409。锁等待后再次检查候选过期。

迁移 0012 新增来源和候选表，降级遇到候选或平台数据拒绝。上线迁移需明确确认目标，测试只在事务随机 schema 执行，不擅自升级现有业务库。

## API 与异常

- POST /job-imports/preview：`{url, mode: "HTML" | "TEXT", content}` → 候选、缺失提示、新建/更新信息；UTF-8 输入上限 1 MiB（1,048,576 字节）、提取 JD 上限 100,000 字符；422 不支持链接、空页、多个职位、无正文。
- GET /job-imports/{id}：候选读取；404 不存在。
- POST /job-imports/{id}/confirm：`{version, confirm: true, fields: {company_name, title, location, raw_jd}}` → 固定回执 `{opportunity_id, posting_id, snapshot_id}`；422 缺确认/缺字段，409 过期/版本、来源或锁超时冲突。

接口统一以 `/api/v1` 为前缀。前端入口位于职位列表“从招聘平台导入”，支持粘贴内容或读取本地 HTML 文件；确认成功后刷新职位列表。失败与取消保留输入，原输入改变或 409 后要求重新预览。

统一响应与 request_id。业务数据库引擎隐藏 SQLAlchemy 回显及包装异常中的绑定参数部分，避免候选与 JD 出现在该参数日志；用户内容不拼入 SQL 字面量。此开关不清洗驱动原始错误或其他应用日志，完整边界见 architecture.md 的数据访问约束。没有外部调用，所以没有网络重试或 SSRF 路径。人工提供内容也不意味着已核实公司性质、行业或岗位外包安排。

## 反方检验与后续条件

定时周期已确认每小时一次，启动当天未跑则补跑；运行重叠跳过而不无限排队的建议见 `job-browsing-design.md` 第 10 节。频率确认不代表平台访问授权或接口限额已验证。

首个验证平台确定为 51job。“更简单”尚未验证；2026-10-05 重新核对官方用户协议仍有自动化接入与内容收集限制，访问入口核对结果见 `job-browsing-design.md` 第 10 节。先确认可用授权方式，再做真实访问验证，不把已有本地解析器当作自动接入证据。

最新确认：策略驱动、启动补跑后续定时、自动保存与自动匹配；具体契约见 `job-browsing-design.md` 第 10 节。人工导入保留候选确认，自动读取路径不伪装成人工确认。此前自动写入待确定项仅剩人工修订冲突等细节，网络接入尚未实施。

每日发现与更新目标已于 2026-10-05 确认，建议接入／失败／单平台验证契约见 [浏览设计第 9 节](job-browsing-design.md#9-每日发现与-jd-更新已确认目标与待确认设计)。当前尚无每日网络扫描实现；平台成功读取时间不能从现有 last_seen_at 回填，自动写入与候选确认的关系须先确定。

最可能失败的是把职位列表、登录页、页面框架或多个 JSON-LD 职位误当单个 JD。首版宁可保留缺失字段或拒绝，不通过 AI 猜测补齐。结构不稳定不增加整站 CSS 选择器猜测。

自动采集下一步需具备：该平台允许的 API/访问授权、脱敏真实页面样本、人工登录可恢复方案、限流与超时、登录失效/验证码/页面改变的失败映射。采用官方接口优先；自动任务状态与来源观察另行建模，首版不预建队列或通用任务引擎。真实站点抓取未验证时，不能将本地样例测试当作上线采集验收。

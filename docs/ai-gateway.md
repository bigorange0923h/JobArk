# 可选大模型服务

> 文件名保留历史命名 `ai-gateway.md`：`gateway` 是代码里的**内部实现名**（OpenAI 兼容协议适配器，
> 见 `backend/app/ai/llm/gateway.py`），不是用户可见产品术语。面向用户的文案统一称“大模型服务”；
> 除非一并提供兼容迁移方案，不要为了统一文案重命名模块或 `JOBARK_AI_GATEWAY_*` 环境变量。

AI 功能默认关闭。本地逐行 JD 提取和字面证据匹配无需外部服务，不能当成语义模型评估或招聘概率。

用户在“AI 模型配置”页面添加 OpenAI 兼容服务商、模型与 API Key，并设置唯一默认模型。新增服务商可在同一表单内一次配置多个模型（模型名称即服务商文档中的模型 ID，同一服务商内不可重复），服务商与其模型在同一事务内保存，任一模型冲突则整体不落库；服务商列表按创建时间倒序展示。API Key 以应用层可逆加密的密文保存在 PostgreSQL，页面和读取 API 仅显示掩码。`JOBARK_AI_CREDENTIAL_ENCRYPTION_KEY` 是数据库外的根密钥；仅 `LOCAL` 环境允许开发默认值，测试与生产必须显式提供。服务商基地址必须为 HTTPS 或本地回环 HTTP，拒绝用户名、密码、查询参数、片段和重定向；本项目不绑定商业 SDK 或代填凭据。

固定任务协议通过**唯一默认启用模型**发送 OpenAI 兼容的结构化输出请求：`POST {base_url}/chat/completions`，请求体包含 `model`、一个系统消息、一个 JSON 用户消息与 `response_format: {"type": "json_object"}`。无默认启用模型、连接失败或结果不符合 Schema 时，均安全失败；每次请求有超时、拒绝重定向且不自动重试，响应体上限 1 MB。领域服务在等待网络前先结束数据库事务，因此外部调用期间不持有事务。

常规日志与响应不得包含文件原文、候选内容或上游响应正文。仅为在 local/test 排查“候选为何缺失、被清空或被改写”，提供默认关闭的诊断开关 `JOBARK_AI_LOG_MODEL_OUTPUT`：开启后模型返回的 JSON 原文会以 `WARNING` 级、`event=ai_model_output` 的日志行输出（含姓名、联系方式等个人信息），生产环境由配置校验在启动时直接拒绝开启；排查完应改回关闭，且不要把这些日志带入共享环境。

`JOBARK_AI_GATEWAY_URL` 与 `JOBARK_AI_GATEWAY_TOKEN` 已废弃：字段名沿用历史命名，仅为不破坏既有 `backend/.env` 而保留，代码不再读取，**永远不得优先于数据库中的默认模型配置**，并将在后续版本移除；请在「AI 模型配置」页面维护服务商、模型与凭据。

`resume_select_existing_items` 输入包含目标方向和已有简历经历、项目、技能、学历、语言条目；不发送 basics/contact。输出为这五类条目的索引列表，只允许筛选和重排。正文从本地原文复制，模型不能创建新技能或业绩。条目自由文本可能包含个人信息，界面需明确确认；请根据大模型服务部署方的数据留存政策决定是否启用。失败保留基线，未确认候选不会覆盖正式版本。

未配置默认启用模型时 AI 功能返回 409 并提示前往「AI 模型配置」；上游不可用时返回安全文案与 `request_id`，原始资料保持不变。连接测试只发送固定 ping 与 `max_tokens=1`，不携带任何业务数据。本地自动测试用替身替换大模型服务，验证成功、错误、越界与确认流程，不代表真实模型服务已联网验收。

`extract_profile_from_resume` 输入为用户明确同意发送的 `resume_text`（可能包含姓名、联系方式、工作、项目与教育信息）及提取规则，不发送 PDF/HTML 原文件。输出请求携带 JSON Schema，后端仍以严格 Pydantic 与逐字证据校验为准：根信封或基本信息锚点无效时预览失败；技能、工作、教育的单条失败仅排除该条。项目名称和摘录是不可放宽的锚点；项目的其他字段缺少逐字证据时清空并在 `warnings` 中列出，保留可确认的项目骨架。为兼容模型沿用工作经历字段命名，项目条目会在校验前做最小归一化（等价字段名如 `title` 补到项目名称、字符串技术栈拆分为列表），归一化只改变字段形态、取值仍须逐字落在摘录中，并通过 `warnings`（`FIELD_ALIAS_MAPPED`）告知。未映射字段只返回字段名诊断，不能静默作为事实导入。条目来源（`origin`）由服务端判定：模型输出的一律按 `RESUME`（简历原文）校验，模型若返回 `origin` 会被剥离并提示；用户新增或改到摘录之外的条目在确认时以 `MANUAL`（本人填写）提交、不需要摘录，服务端据此分别挂简历摘录证据与本人陈述证据，两类都保持未验证。个人简介与公开链接按字段级隔离校验：链接地址允许模型补上协议前缀（比较时去掉前缀），链接名称与个人简介同样必须逐字来自原文；定位不到时只清空这两个字段并在 `warnings` 中列出，不会因为一段被润色过的自我评价就让整次抽取失败。确认阶段用户补充到摘录之外的内容作为本人陈述写入；已有档案时这两个字段不覆盖。预览不写数据库，仅对连接失败、429、5xx 自动重试一次；超时、非 JSON 和其他协议失败不重试。若大模型服务未配置，页面返回 409 并保留手工建档路径。此任务当前只有替身测试验证，接入真实部署方前需用户确认数据流向与留存政策。

本地联调导入链路时，可开启默认关闭的内置夹具 `JOBARK_PROFILE_IMPORT_FIXTURE`：用内置样例简历（`modules/profile/import_fixture.py`）与固定抽取结果替代 `extract_profile_from_resume` 的模型调用，因此不需要配置服务商与凭据（联调期间 `import_service` 里的 `_FORCE_MOCK_EXTRACTION_IN` 常量把 local 环境临时强制为 mock，恢复真实调用时改回 `None`）。夹具只替换外部输入——固定结果与样例文本互相自洽，候选仍要经过同一套 Schema 与逐字证据校验，确认写入时也用同一份样例语料核对，不放宽任何检查。预览响应带 `fixture=true`，界面必须提示“内置模拟数据，未调用大模型服务”。仅 local/test 可用，生产环境由配置校验在启动时拒绝开启。

`jd_requirements_with_verbatim_quotes` 输入仅为所选快照的 `raw_jd`。输出需满足请求中的 JSON Schema；每项 `text` 与 `source_quote` 必须一致，且逐字出现在原文中。标签和强制性仍需人工核对。`POST /api/v1/job-snapshots/{id}/parses` 创建独立的 PARSED 或 FAILED 解析记录；201 表示记录创建成功，不代表解析成功，调用方必须检查 `status`。失败仅保存安全错误码，不持久化上游原始响应，也不改变 JD 快照。GET 同路径读取历史。

匹配接口 `POST /api/v1/matches` 默认不调用大模型服务，只使用快照原文和固定资料修订做本地技能字面证据检索；教育、年限等无法证明的条件保留为未知。它不会自动采用 AI 解析结果，也不生成隐含的满足结论。

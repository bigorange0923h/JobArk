# AI 模型配置需求与验收标准

## 1. 目标与范围

JobArk 是单人本地求职工作台。用户可以在工作台内维护多个 AI 服务商和多个模型配置，选择唯一的默认启用模型，供现有的、仍需用户明确同意的 AI 候选功能使用。

本功能只支持 **OpenAI 兼容协议**。服务商配置不是平台 SDK 集成；用户自行确认服务商的数据处理政策、可用模型和计费规则。V1 不提供按简历优化、职位解析等用途分别分配模型的能力，也不改变任何外部发送前的确认边界。

## 2. 用户可见能力

- 工作台侧栏新增“AI 模型配置”入口。
- 用户可以新增、编辑、停用和删除服务商；服务商至少包含显示名称、兼容接口基地址、可选 API Key 和可选说明。
- 用户可以在服务商下新增、编辑、停用和删除模型；模型至少包含显示名称和远端模型标识。一个服务商下的模型共用该服务商的 API Key。
- 首次保存成功的模型自动成为默认启用模型；之后同一时刻最多只有一个默认启用模型，用户可显式切换。
- 用户可测试已保存配置的连通性。测试仅发送最小的协议请求，不产生简历、档案、职位、匹配或投递业务事实。
- 已保存 API Key 在页面和读取 API 中仅显示“是否已配置”及固定掩码或末尾标识；创建和替换 API Key 时才接收明文。

## 3. 安全与数据边界

- API Key 必须以可逆加密密文保存到数据库，供服务端在实际请求时解密；禁止保存、记录或返回明文。
- 加密根密钥必须在数据库外：本地开发环境可使用代码内的开发默认值；测试与生产环境必须由 `JOBARK_AI_CREDENTIAL_ENCRYPTION_KEY` 显式提供，缺失时拒绝保存或调用带凭据的配置。
- 编辑服务商且未提交新的 API Key 时，必须保留已有密文；提交空值不得意外清除凭据。删除模型或服务商必须经前端明确确认；删除服务商后不可恢复其 API Key。
- 只允许 HTTPS 基地址，或 `localhost`、`127.0.0.1`、`::1` 的 HTTP 基地址；拒绝包含用户名、密码、查询参数、片段或重定向的地址。
- 默认模型只是服务端调用的候选配置来源，不能绕过资料外发确认、输出 Schema 校验、超时、无自动重试和“AI 不写业务事实”的既有约束。

## 4. 一致性与失败反馈

- 服务商或模型名称、接口地址和远端模型标识必须进行空值、长度和格式校验；同一服务商下远端模型标识不可重复。
- 默认模型必须处于启用状态，所属服务商也必须启用。停用或删除默认模型前，用户必须先设置另一个启用模型为默认；没有替代模型时给出冲突反馈。
- 模型的连接测试失败时，不改变默认状态、凭据或业务数据；页面显示安全错误文案与 `request_id`（如有）。
- 模型配置变更是配置记录，不追溯改写已存在的 AI 候选稿或业务事实。

## 5. 验收标准

- 在空配置环境创建首个服务商和模型后，该模型被保存且成为唯一默认模型；读取结果不含 API Key 明文或密文。
- 可在同一服务商下保存多个模型、在不同服务商下保存模型，并能将任一启用模型切换为默认，系统始终只保留一个默认模型。
- 非 OpenAI 兼容地址、非安全地址、无模型名、重复远端模型标识、无可用默认模型的操作返回统一错误契约和清晰文案。
- 本地开发默认密钥可完成加密往返；测试或生产环境缺少显式加密根密钥时拒绝敏感配置操作。
- 服务商 API Key 的替换、保留、掩码读取、停用、删除确认和连接测试失败均有自动化覆盖；现有 AI 功能改为使用默认模型后，仍要求用户明确同意发送资料。
- 新页面具有加载、空、失败、正常和写入忙碌状态，窄窗口无页面级横向溢出；前端 lint、类型检查、测试和生产构建通过，后端类型检查、lint、迁移与隔离数据库测试结果如实记录。

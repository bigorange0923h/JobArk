# 职位录入、采集与投递的分阶段范围

2026-10-06 用户确认：复制 JD 为主入口，自动采集与确认后自动投递为辅助，按阶段实施。本文件扩展 V1 的后续目标，不表示平台自动化已经可用。执行状态以 GitHub Issue 为准，本文件只保存范围、依赖与验收。

## 阶段一：复制 JD 与来源记录

- **JIS-01**：复制 JD 是主入口。有效 JD 即可保存并评估，公司资料缺失不阻断；无法识别的公司与标题明确缺失，不生成假事实。复用既有解析、档案匹配与简历匹配，不新增平行评分。
- 每个来源记录可选择 BOSS 直聘、LinkedIn、Indeed、前程无忧、公司官网或其他自定义渠道；链接可选。旧记录不猜测渠道。
- `channel_name` 保存用户声明的渠道，现有 `source` 保留导入适配器来源语义；手工录入仍为 MANUAL，选择渠道不代表平台已读取或验证。
- 公司官网、行业、所在地和介绍可手动补充；现有 HTML 导入仅提取明确支持的结构化字段作为核对候选，不新增网络请求或无依据推断。不能提取时由用户复制或填写，不阻断已有 JD 评估。
- 公司介绍保存为用户提供内容，不自动产生已确认性质/行业分类。公司名称不作为自动合并依据。
- 保存失败保留全部输入；详情回读渠道和公司资料。既有 JD 不可变快照与匹配输入绑定不变。
- **JIS-02**：提取结果是待核对候选，保留原文、逐字段来源与人工修订；可靠已有公司资料减少重复填写，缺失可手工补充。不同渠道或同名公司不自动合并，无链接手工记录不自动绑定后续平台记录。
- **JIS-03**：逐条件展示硬性声明、档案事实与证据、缺口、不确定项及简历表达问题；区分档案有事实但简历未表达、档案未记录、无法判断；字面命中不等于核实能力，不提供未经校准总分。
- 验收覆盖只有 JD、无链接、常用/自定义渠道、空白和超长输入、旧请求兼容、公司信息回读、候选／失败保留、解析失败与保存成功分离；历史不编造来源。此前 0013 仅增加可空字段，JD-only 的具体兼容迁移另行设计及授权，不改写历史事实。

## 阶段二：单平台只读自动采集

- 依赖：验证目标平台许可、实际访问方式及运行环境；先单平台再扩展，不承诺全部平台。
- 延续 job-browsing.md 已确认的策略扫描、启动检查、定时、自动保存与匹配目标；自动读取不冒充人工确认。
- 明确获取的公司信息记录来源；冲突保留人工维护结果。提取失败保留已有内容并提供手动复制入口。
- 验收包含登录失效、验证码、页面变化、超时、内容缺失及并发更新；失败不推进成功读取时间或覆盖当前 JD。
- **JIS-04**：保留内容版本与每次正式保存／平台获取尝试的不同记录；重复正文可复用快照，失败、未运行和成功分别显示。系统接收时间、平台读取成功、内容首次采集和平台声明发布不能互代，未知保持未知。
- **JIS-05**：人工修订不被自动更新静默覆盖，跨来源默认选择也须遵守保护；冲突保留候选及人工采用入口，历史查看不写当前指针。
- **JIS-06**：沿用已确认的 51job 单平台验证、策略扫描、启动当天未尝试补跑和运行期间每小时执行；关闭／休眠不保证执行。防并发重入，持久化运行／失败／恢复证据，有界只读重试；自动保存有效 JD 后固定输入匹配，失败不丢已保存内容。
- **JIS-07**：采集许可、模型外发确认和投递授权彼此独立；自动匹配不得隐式外发个人资料。真实平台许可和读取完整性未通过则保持不可用，不能用本地测试代替。

## 阶段三：单平台确认后自动投递

- 依赖：阶段二的平台验证及独立的执行审计、幂等与回执方案；实施前完善对应接口和状态验收。
- 用户选择职位和正式简历版本，查看实际提交内容并逐次明确授权；任务固定 JobSnapshot、ResumeVersion 和确认内容。
- 投递适配器独立于领域服务；Application 状态仍只通过 ApplicationEvent 变更。只有可靠成功回执或用户明确核实才能记录已投递。
- 超时或连接中断导致结果未知时等待核实，不自动重复提交；登录失效、验证码或材料缺失转人工，保留进度。
- 验收覆盖拒绝未确认执行、确认后材料变化、重复执行、成功回执、明确失败、结果未知及人工接管；代码测试不能代替真实平台验收。
- 本次范围确认不授权向具体招聘方提交真实简历，实际提交仍须确认目标和材料。
- **JIS-08**：逐次发送授权绑定目标岗位／渠道／账号、JobSnapshot、正式 ResumeVersion 以及实际字段、回答、问候语与附件；相关内容或目标变化作废授权，不能悄悄替换。
- **JIS-09**：执行任务／尝试与 Application 求职状态分开，可靠成功或明确历史陈述通过 ApplicationEvent 留痕；证据类型区分平台验证与用户陈述。重复确认／申请、并发、重启和取消竞态必须受控。
- **JIS-10**：提交可能发生后连接中断属于结果未知，先核实，禁止盲目重试；额外问题、验证、登录失效、缺材料暂停转人工。撤销本地授权不保证撤回已发平台请求。
- **JIS-11**：实际预览不提前上传材料；不存明文密钥、Cookie、OTP或浏览器 Profile 到仓库／业务日志。平台缺少稳定提交与可核实回执，降级下载／复制材料、用户自行操作及如实历史记录。

## 统一验收边界

**JIS-12**：读取加载、空数据、失败分别表达；字段错误／冲突／失败保留输入，未知时间不伪造，原文不丢失。桌面及窄窗口沿用既有 Ant Design Vue、主题与错误反馈；新 API 保持统一响应和中文说明。

各阶段分别报告自动测试、浏览器验收和真实平台验证，数据库测试只在现有随机 schema 隔离范围执行。具体建议、状态／接口／审计与停止条件见[详细设计](../job-intake-and-submission-design.md)，实施依赖和可复制 Issue 见[实施拆分](../implementation/job-intake-and-submission-issues.md)。这些设计建议不自动升级为已批准 schema；任务状态只在 GitHub。

## 2026-10-07 分析范围修订

本轮以 [JD 分析正式需求](jd-analysis.md) 和 ADR 0007 为准。允许新 schema 的可解释 10 分参考区间；旧 overall_score 保持 null，不回填。未知不计零，硬限制优先，禁止录用概率、无依据总分和自动淘汰。JobOpportunity.company_id/title 可空，Company.name 仍必填，不建占位公司。ProfilePreference 增加有版本的目标方向、显式硬限制口径和优先名单；旧偏好不升级为硬限制。MatchResult 增加可空成功解析引用，报告 JSON 冻结必要策略、条件与算法/模型版本并记录内容指纹。公司公开报告及来源归 Job，独立不可变，不改变确认分类或能力分。外发确认和事务边界沿用既有约束；自动采集、调度、外部投递不在本轮实现范围。本文是后续范围决策，不是实现或真实运行验收声明。

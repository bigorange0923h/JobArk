# 职位录入、采集与投递的分阶段范围

2026-10-06 用户确认：复制 JD 为主入口，自动采集与确认后自动投递为辅助，按阶段实施。本文件扩展 V1 的后续目标，不表示平台自动化已经可用。执行状态以 GitHub Issue 为准，本文件只保存范围、依赖与验收。

## 阶段一：复制 JD 与来源记录

- 手工入口优先展示，保存公司、岗位与原始 JD 后复用既有解析、档案匹配及简历匹配；不新增平行评分。
- 每个来源记录可选择 BOSS 直聘、LinkedIn、Indeed、前程无忧、公司官网或其他自定义渠道；链接可选。旧记录不猜测渠道。
- `channel_name` 保存用户声明的渠道，现有 `source` 保留导入适配器来源语义；手工录入仍为 MANUAL，选择渠道不代表平台已读取或验证。
- 公司官网、行业、所在地和介绍可手动补充；现有 HTML 导入仅提取明确支持的结构化字段作为核对候选，不新增网络请求或无依据推断。不能提取时由用户复制或填写，不阻断已有 JD 评估。
- 公司介绍保存为用户提供内容，不自动产生已确认性质/行业分类。公司名称不作为自动合并依据。
- 保存失败保留全部输入；详情回读渠道和公司资料。既有 JD 不可变快照与匹配输入绑定不变。
- 验收覆盖无链接、常用/自定义渠道、空白和超长输入、旧请求兼容、公司信息回读和失败保留；迁移只增加可空字段，不改写历史数据。

## 阶段二：单平台只读自动采集

- 依赖：验证目标平台许可、实际访问方式及运行环境；先单平台再扩展，不承诺全部平台。
- 延续 job-browsing.md 已确认的策略扫描、启动检查、定时、自动保存与匹配目标；自动读取不冒充人工确认。
- 明确获取的公司信息记录来源；冲突保留人工维护结果。提取失败保留已有内容并提供手动复制入口。
- 验收包含登录失效、验证码、页面变化、超时、内容缺失及并发更新；失败不推进成功读取时间或覆盖当前 JD。

## 阶段三：单平台确认后自动投递

- 依赖：阶段二的平台验证及独立的执行审计、幂等与回执方案；实施前完善对应接口和状态验收。
- 用户选择职位和正式简历版本，查看实际提交内容并逐次明确授权；任务固定 JobSnapshot、ResumeVersion 和确认内容。
- 投递适配器独立于领域服务；Application 状态仍只通过 ApplicationEvent 变更。只有可靠成功回执或用户明确核实才能记录已投递。
- 超时或连接中断导致结果未知时等待核实，不自动重复提交；登录失效、验证码或材料缺失转人工，保留进度。
- 验收覆盖拒绝未确认执行、确认后材料变化、重复执行、成功回执、明确失败、结果未知及人工接管；代码测试不能代替真实平台验收。
- 本次范围确认不授权向具体招聘方提交真实简历，实际提交仍须确认目标和材料。

# JD 分析可靠性修改计划

2026-10-07 用户确认依据只读评估实施调整。本文记录修改范围、依赖与验收；GitHub Issue/Project 仍是协作状态来源，不把本文作为第二份任务状态表。

## 范围与顺序

1. P0：JD 条件拆分、原文位置和并列关系。排除标题行，避免“开发”一词覆盖技能/学历/年限分类；未识别准入保持未知。OR 组合保留为一个待确认条件，不把替代项全部当必需。
2. P0：目标方向和补充关键词分开；结合职位标题及职责提供保守线索，不从履历猜用户意愿。薪资区分期望区间与可选最低可接受月薪；同币种、周期和税口径比较，超过期望上界不扣分，跨底线待确认。
3. P0：教育增加可空学历层次与学习形式，保留旧 degree 文本且不回填、不推定全日制；贯通 API、导入确认、修订与表单。非全日制不能自动推导为学历不合格。
4. P0：报告显示事实引用、摘录支持与本人陈述的区别；针对未配置策略、空项目技术栈/归属、缺少来源支持输出可行动补充提示，不把选填缺失视为错误。
5. 验证：先缺陷复现，再逻辑/API/前端回归和随机 schema 迁移升降级、ORM 对齐。业务库升级先核对目标及影响，迁移只增加结构和默认空值，不修改真实履历、薪资和方向；个人数据升级前后做摘要校验且不输出正文/凭据。

## 明确不做

不代填项目技术栈、工作归属、学习形式、到岗时间或求职意愿；不从总工龄推算 AI 工龄；不增加主观能力总分、录用概率、复杂权重配置、通用证书库或自动投递。出差/驻场/工作时间等待有明确筛选需求再设计。

## 验收条件

- 同句技能、年限、学历独立展示，原文位置可验证；标题不评分，否定和 OR 不产生确定冲突，解析遗漏不能产生 NOT_APPLICABLE。
- 标题方向线索与正文关键词线索可区分；未知方向不当不匹配。旧策略内容保持兼容，新增字段空值不改变旧用户意愿。
- 明确同口径薪资低于可接受底线产生硬冲突；达到底线但低于期望为部分适合；高于期望区间不扣分；跨底线/缺口径为待确认。
- 教育新字段只接受合法枚举，可清空；修改后归因和历史修订正确，旧 degree 保留。
- 摘录定位校验不宣称独立核验；模型、本地、数据库与浏览器验收分别记录。

# ADR 0004：数据库保存受控 AI 模型配置

## 状态

已接受。

## 背景

现有 AI 网关仅从 `backend/.env` 读取单个 URL 与 Token，不能让单人用户在产品内维护多个模型，也不能安全地读取或掩码展示已保存凭据。直接把 API Key 明文保存到数据库或返回给前端不满足敏感信息边界；为每个商业服务商引入 SDK 又会扩大 V1 的协议与维护范围。

## 决定

新增 `ai` 基础设施子域，使用 PostgreSQL 保存服务商、模型及其受保护凭据：

- 服务商固定为 OpenAI 兼容 HTTP 协议配置，不接入厂商专有 SDK。
- 服务商持有加密后的 API Key 与非敏感掩码，模型只持有远端模型标识和唯一默认标记；同一服务商下的模型复用凭据。数据库约束和服务层事务共同保证默认模型至多一个；首次创建模型时自动设为默认。
- API Key 用应用层可逆加密。根密钥由 `JOBARK_AI_CREDENTIAL_ENCRYPTION_KEY` 提供；仅 `LOCAL` 环境允许开发默认值，其他环境缺失时安全失败。
- 路由层只返回可展示的配置 DTO，永不返回密文或明文。凭据替换采用写入专用字段，空字段语义为“不变”。
- `app.ai.llm.gateway` 保持固定任务、Schema、超时、禁止重定向和不自动重试的职责；它通过默认模型配置构造 OpenAI 兼容请求，而不是让领域模块了解服务商细节。

## 后果

用户可以保存多个模型并选择唯一默认模型，后续可用稳定模型 ID 扩展用途级路由。配置删除会清除其密文且不可恢复，因此必须由 UI 明确确认。V1 不增加模型路由策略、调用计费统计或厂商专用特性；这些需求需要新的 ADR 和验收标准。

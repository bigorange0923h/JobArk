# ADR 0003：求职闭环与分析边界

## 决策

申请管理是人工记录流程。记录 APPLIED 仅表示用户确认已经投递，不调用外部平台。创建时固定职位快照和简历版本；重试申请显式确认，attempt_no 在职位行锁内分配。状态更新用乐观锁，事件与投影同事务提交。

允许 SAVED → PREPARING → READY_TO_APPLY → APPLIED → CONTACTED → INTERVIEWING → OFFERED；人工补录允许从投递前状态直接进入 APPLIED，从 APPLIED 直接进入 INTERVIEWING。非终态可 WITHDRAWN/CLOSED，投递后可 REJECTED；终态不能再次迁移，重新申请产生新尝试。

JD 原文和快照保持不可变。解析需要独立版本化产物，失败保留原文及安全错误，不覆盖历史快照。匹配绑定 JobSnapshot、ProfileRevision 和可选 ResumeVersion，报告内固化本地解析结果及解析器版本；单独生成的 AI 解析产物不自动成为匹配依据。未经校准的评分不作为录用概率或自动淘汰依据；缺证据归为未知，不等同不满足。

AI 优化仅产生候选建议，保留输入版本及依据，用户对比确认后创建正式版本。外部模型能力默认关闭；开启前配置明确的服务地址、模型、超时和凭据。只发送该操作必需的数据，不发送联系方式，不在数据库事务中等待模型。

Dashboard 从申请及事件读取计数，不维护第二份事实。漏斗表示曾到达阶段的尝试数，趋势按 UTC 日期计算，版本转化以申请尝试为分母并明确样本数。

## 验证

必须覆盖非法流转、重复确认、过期版本、错误快照归属、外部解析失败和证据缺失。数据库验证只作用于独立测试库，开发库迁移单独执行。
